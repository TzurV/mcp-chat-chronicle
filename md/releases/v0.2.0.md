# Chat Chronicle v0.2.0

Chat Chronicle v0.2.0 adds local, read-only MCP recall for tested Codex and
Claude clients. A supported local client launches Chronicle as a child process,
searches the existing SQLite/FTS archive, retrieves selected bounded evidence,
and writes the final answer while citing Chronicle conversation IDs.

## MCP recall highlights

- Chronicle remains a local archive; MCP neither captures nor refreshes history.
- FastMCP uses local stdio transport and opens the selected SQLite database
  read-only.
- Exactly three tools are exposed: `search_chats`, `get_conversation`, and
  `list_recent_topics`.
- Search and recent-topic results are bounded; conversation detail is limited
  by `max_chars`.
- Archived transcript text is treated as untrusted evidence, not instructions
  to the calling model.
- There are no write, migration, enrichment, capture, or arbitrary-SQL tools.

The integration was tested with Codex in VS Code, the Windows Codex/OWL app,
Claude Code, and Claude Desktop. Classic ChatGPT Windows, ChatGPT web,
`claude.ai`, mobile clients, and remote sessions are not local stdio MCP
targets.

Install the optional MCP dependencies with:

```powershell
poetry install -E mcp
```

Then follow the
[MCP Recall User Manual](https://github.com/tzurv/mcp-chat-chronicle/blob/v0.2.0/docs/mcp-client-setup.md).
The tested direct Windows launch is:

```text
<repo>\.venv\Scripts\python.exe -m chat_chronicle.cli serve
```

## Illustrative prompts

All topics, dates, and IDs below are fictional:

```text
Using my Chronicle archive, what did I work on during the fictional Project
Lighthouse migration last week? Include dates and supporting Chronicle IDs.
```

```text
Search Chronicle for the conversation where I fixed a fictional Windows
terminal-wrapping test. Return likely matches first; do not retrieve full
transcripts yet. Cite the matching Chronicle IDs.
```

```text
Retrieve fictional conversation 123 with at most 2,000 characters and summarize
the decision, blocker, and next action. Cite the Chronicle ID.
```

```text
Compare the decisions recorded in fictional conversations 123 and 456. Cite
both IDs and distinguish recorded facts from your interpretation.
```

```text
List my five most recently active Chronicle topics with dates and IDs, using
metadata only.
```

## Privacy and cloud processing

The database and MCP server stay local. Search results or bounded conversation
text selected by an MCP call become part of the AI client's model request. In a
cloud-backed Codex or Claude client, that selected output is therefore processed
by OpenAI or Anthropic under the user's account and provider settings.

Deliberately allowing more relevant conversations or larger bounded extracts
can give the model more evidence and produce a richer, better-grounded answer.
That is a user-controlled context/privacy tradeoff, not an automatic bulk export
of the archive. Search metadata first, retrieve only selected IDs, set
`max_chars`, and avoid secrets or third-party confidential data.

Chronicle's normal SQLite/FTS CLI workflow remains local and requires no model.
MCP disclosure depends on the selected client and its configured model provider;
the tested Codex and Claude client paths are cloud-backed. Separately, optional
Chronicle AI tasks can use local models through the documented LM
Studio/LiteLLM path.

## Other accepted changes since v0.1.0

MCP recall is the headline, but the source diff since v0.1.0 also includes:

- optional YAML-defined AI tasks through LiteLLM, with strict structured
  outputs, configuration-aware caching, and provenance;
- local LM Studio compatibility and four initial conversation-intelligence
  task contracts;
- split candidate-generation, package-verification, deterministic-scoring, and
  optional judge tooling for development evaluation;
- documentation and operational guidance for collection, AI tasks, evaluation,
  MCP clients, and privacy boundaries;
- expanded tests plus Windows/Ubuntu CI and Windows terminal/file portability
  fixes.

Private evaluation corpora, model outputs, databases, exports, credentials, and
local client settings are not release artifacts.

## Upgrade from v0.1.0

From an existing source checkout:

```powershell
git fetch --tags
git checkout v0.2.0
poetry install -E mcp
poetry run chronicle --version
```

This intentionally checks out the immutable `v0.2.0` release tag rather than
installing whichever commit is currently at the tip of `main`.

Run `poetry run chronicle collect` to refresh the archive. Existing MCP users
should keep the stable server command and change only `CHAT_CHRONICLE_DB` when
switching databases, then restart the client.

This remains a source release installed with Python 3.11+ and Poetry. PyPI and
pipx packaging are not included.

## Known limitations

- MCP does not ingest history; users still run `chronicle collect`.
- MCP cannot capture the current chat or infer its Chronicle conversation ID.
- No MCP tool writes, migrates, enriches, or accepts arbitrary SQL.
- Local stdio MCP is unavailable in many web, mobile, classic desktop, and
  remote clients.
- Setup currently assumes a source checkout and Poetry virtual environment.
- Topic quality depends on imported source metadata or previously stored valid
  summaries; no model runs during normal MCP calls.
- Embeddings/hybrid search, remote MCP hosting, PyPI/pipx distribution, and the
  WorkTrail rename remain future work.

## Next local-AI direction

The optional advanced infrastructure and initial contracts already exist.
Future work will improve local-model reliability, prompting, evaluation, and
eventually richer local archive intelligence without slowing normal SQLite/FTS
search. The intended workflow is asynchronous, cacheable, externally configured
through YAML task/model definitions, and local-model-first where practical.
Stronger remote models may be used during controlled development or evaluation.

The four conversation-intelligence tasks are:

1. a concise summary with deterministic start and last-active dates;
2. work-mode classification as `manager`, `executor`, `one_off`, `mixed`, or
   `unknown`;
3. the most recent activity, blockers, and next action;
4. title assessment and a suggested replacement without automatic renaming.

This enrichment is not automatic, production-complete, or part of normal MCP
calls.
